# 企業如何用 RAG 整合內部資料？需要搭配 MCP 嗎？

> 資料來源：Claude Code 官方〈[Connect Claude Code to tools via MCP](https://code.claude.com/docs/en/mcp.md)〉；RAG 流程與企業要件為業界通行做法的整理；本庫〈[Post-Training](Post-Training.md)〉的「企業知識整合」三節。

## 一、先給答案

| 問題 | 簡短回答 |
|------|----------|
| RAG 是在「訓練」內部資料嗎？ | **不是。** RAG 不改模型權重；每次回答前先去你的資料檢索相關片段，放進 prompt，讓模型依據這些片段回答。資料更新只要重建索引，不必重訓。 |
| 企業怎麼做？ | 離線建索引（清洗、切塊、附權限 metadata、向量化），線上檢索（依使用者權限過濾、重排）後生成附引用的答案，並持續評估與稽核。 |
| 一定要 MCP 嗎？ | **不一定。** 只做「查文件回答問題」，RAG 本身就夠。需要**即時資料**、**執行動作**，或讓**多個 AI 應用共用同一接口**時，再加 MCP。 |
| 兩者的關係？ | 不同層次：RAG 是一種「檢索後再生成」的做法；MCP 是讓 AI 應用連接外部工具與資料的**協定**。常見組合是把 RAG 檢索服務包成一個 MCP server。 |

---

## 二、RAG 在做什麼，不在做什麼

- **做**：在回答時，把與問題相關的內部文件片段找出來，附在 prompt 裡。模型「讀到」資料，但沒有「學會」資料。
- **不做**：不改變模型的風格、格式遵循、領域推理能力。這些要靠微調或後訓練，是另一件事，見〈[Post-Training](Post-Training.md)〉的「企業知識整合：RAG 夠不夠？」。
- **知識與行為分工**：RAG 管**事實**（最新、可追溯、可刪除），微調管**行為與格式**。兩者是搭配，不是二選一。🛠

## 三、企業 RAG 的標準流程

![企業 RAG 的兩條線：離線建索引（資料來源、清洗去重、切塊加 metadata、向量化、索引）與線上查詢（提問加身分、依權限過濾檢索、重排、組 prompt、生成附引用的答案），底部是橫跨兩邊的評估、稽核與同步](figures/enterprise-rag-pipeline.svg)

### 3.1 離線：建索引 🛠

| 步驟 | 做什麼 | 實務重點 |
|------|--------|----------|
| 盤點資料 | 文件、wiki、工單、程式碼、資料庫匯出 | 先決定哪些**能進**、哪些**不能進**（機密、個資、未定稿） |
| 清洗與去重 | 移除過期版本、重複內容、雜訊（頁首頁尾、目錄） | 同一份規章有多個版本時，要有「現行版」標記，否則模型會引用舊版 |
| 切塊（chunking） | 依章節或語意切成片段 | 太小丟失上下文、太大稀釋重點；表格與程式碼要保持完整 |
| 附 metadata | 來源、版本、部門、建立與修改時間、**權限** | 權限必須在這一步寫進去，後面才有東西可以過濾 |
| 向量化 | 用 embedding 模型把片段轉成向量 | 換 embedding 模型就要整批重建索引 |
| 建索引 | 向量索引，加關鍵字索引（hybrid） | 產品型號、錯誤碼、條款編號這類精確字串，關鍵字檢索通常比純向量準 |

### 3.2 線上：回答問題 🛠

| 步驟 | 做什麼 | 實務重點 |
|------|--------|----------|
| 帶身分提問 | 請求附上使用者身分 | 身分決定能看哪些文件 |
| 檢索 | hybrid 取 top-k 候選 | **先依權限過濾，再取 top-k**；反過來做，可能漏掉有權限但排名低的文件 |
| 重排（rerank） | 用更精準的模型從候選中挑出最相關幾段 | 通常是品質提升最明顯的一步 |
| 組 prompt | 把片段與問題組在一起 | 指示「只依據提供的片段回答，找不到就說不知道」，並要求附引用 |
| 生成 | 語言模型產生答案 | 答案附來源，使用者能回到原文核對 |

### 3.3 常見的品質問題與先查哪裡

| 現象 | 先查 |
|------|------|
| 答案沒有用到明明存在的文件 | 檢索：切塊、hybrid、重排、metadata 過濾條件是否誤殺 |
| 引用了舊版內容 | 資料：版本標記、同步是否漏掉修訂與刪除 |
| 找到了文件但答錯或亂編 | 生成：prompt 約束、模型選擇；必要時才考慮微調（見 Post-Training） |
| 跨多份文件的總結不完整 | top-k 片段看不到全貌；考慮 Agentic RAG、分層摘要等進階做法 |

先拿**一份真實問題集**量測「檢索命中率」與「答案正確率」，再決定改哪裡；沒有評估集就改，只是憑感覺。🛠

## 四、企業環境的硬性要求

| 要求 | 做法 | 為什麼 |
|------|------|--------|
| **權限** | 檢索時依使用者身分過濾（文件級或欄位級 ACL，隨 metadata 一起進索引） | 模型不會自己守權限；漏進 prompt 的內容就可能被問出來 |
| **資料新鮮度** | 增量同步；刪除與修訂要能從索引移除 | 否則答案會引用已撤銷的規定 |
| **可追溯** | 每個答案附引用並保留來源連結 | 稽核與使用者核對 |
| **稽核紀錄** | 記錄誰在何時問了什麼、用了哪些文件 | 合規、事後調查 |
| **資料不外流** | 選用符合合規的部署方式與服務條款；敏感文件分級 | 內部資料會被放進 prompt 送給語言模型 |
| **評估與監控** | 固定評估集、線上回饋、定期回歸測試 | 資料與模型一變，品質就可能退步 |

> 是否一定要自己部署開源模型，取決於合規與成本；只做 RAG 不等於一定要開源，詳見〈[Post-Training](Post-Training.md)〉的「只做 RAG，還需要開源模型嗎？」。

## 五、需要整合 MCP 嗎？

![RAG 與 MCP 並用的架構：AI 應用內的 MCP client 連到三類 MCP server——文件檢索（背後是 RAG 索引，唯讀）、業務系統查詢（背後是資料庫，即時資料）、動作（背後是工單或審批系統，會寫入）；每條連線都要最小權限、依使用者身分過濾、記錄呼叫，寫入類工具要審核](figures/enterprise-rag-mcp.svg)

### 5.1 MCP 是什麼

- ✅ 依 Claude Code 官方文件：MCP 是一個**開放標準**，讓 Claude Code 能存取外部工具、資料庫與 API。官方的情境是「當你本來要從別的工具把資料貼進對話時，就連一個 server」。
- ✅ 官方列的例子：從 JIRA 的 issue 實作功能並開 GitHub PR、查 Sentry 與 Statsig、查 PostgreSQL、依 Figma 設計更新郵件範本、建立 Gmail 草稿。
- ⚠️ 協定層：一般理解 MCP server 可暴露「工具（tools）、資源（resources）、提示（prompts）」等能力，由 AI 應用內的 MCP client 連接。這點沒有對照規格站驗證。

### 5.2 RAG 與 MCP 怎麼分工

| | RAG | MCP |
|---|-----|-----|
| 本質 | 一種做法：檢索後再生成 | 一個協定：統一連接工具與資料的方式 |
| 適合 | 大量非結構化文件（規章、手冊、知識庫） | 即時查詢系統（資料庫、工單、CRM）與執行動作 |
| 資料型態 | 預先建索引，有新鮮度延遲 | 通常直接呼叫來源系統，取得當下的值 |
| 能否做動作 | 只讀取 | 可以（建單、寫入、觸發流程） |
| 主要風險 | 權限外洩、引用舊資料 | 過大的權限、prompt injection、寫入誤操作 |

### 5.3 什麼時候需要加 MCP

- 答案要的是**現在的值**：庫存、訂單狀態、值班表。這種資料不適合預先索引。
- 要讓 AI **執行動作**：建單、審批、寫入。
- **多個 AI 應用**要共用同一個資料接口，不想每個應用各寫一套連接器。🛠
- 想讓內部系統**對 Claude Code 等工具開放**，用標準方式連接。✅

### 5.4 常見的組合方式

把 RAG 檢索服務包成一個 **MCP server**（唯讀），再與其他 MCP server（即時查詢、動作）一起交給 Agent，由 Agent 決定何時呼叫哪一個。🛠 這是業界常見的做法，不是 MCP 規定的。

**不建議**：用 MCP 逐一呼叫工具去讀大量非結構化文件。這會又慢又貴，排序品質也不如專門的檢索管線。🛠

## 六、用 MCP 時的安全與成本（依 Claude Code 官方文件）

### 6.1 安全 ✅

- 官方警告：「**Verify you trust each server before connecting it. Servers that fetch external content can expose you to prompt injection risk.**」（連接前先確認你信任該 server；會抓取外部內容的 server 可能帶來 prompt injection 風險。）
- 專案層的 `.mcp.json` 裡的 server，Claude Code 在互動 session 使用前會**要求你核准**；被 clone 下來的 repo 不能替自己核准 server。
- 遠端 server 的 `url` 與 `headers` 裡的憑證變數（如 `ANTHROPIC_API_KEY`）讀出來是空的，專案設定無法把你的憑證送到它指定的 server。
- 連資料庫時，官方範例建議使用**唯讀**的資料庫帳號。
- 移除遠端 server 只會刪除本機儲存的 OAuth token，**不會撤銷**；要撤銷先執行 `claude mcp logout <name>` 再 `claude mcp remove <name>`。

### 6.2 範圍與組織管控 ✅

| Scope | 載入範圍 | 是否與團隊共享 | 存放位置 |
|-------|----------|----------------|----------|
| Local（預設） | 僅目前專案 | 否 | `~/.claude.json` |
| Project | 目前專案 | 是（進版控） | 專案根目錄的 `.mcp.json` |
| User | 你的所有專案 | 否 | `~/.claude.json` |

- 同名 server 在多處定義時，優先序是 local → project → user → plugin 提供的 → claude.ai connector；欄位**不合併**。
- 組織可用 `managedMcpServers`（優先於其他來源）、`managed-mcp.json`、`allowedMcpServers`／`deniedMcpServers` 控管。被擋的 server 會在 `/mcp` 顯示 `Blocked by enterprise managed policy`。
- 完整的允許／拒絕清單語法在另一頁〈Managed MCP〉，本文未展開。

### 6.3 傳輸與驗證 ✅

- 遠端 server 建議用 **HTTP**；SSE 已標為棄用；本機行程用 **stdio**。
- 需要登入的遠端 server 用 `/mcp` 或 `claude mcp login <name>` 做 OAuth；`claude -p` 與 Agent SDK 無法完成 OAuth 流程，要先互動登入。

### 6.4 context 成本 ✅

- Claude Code 預設開啟 **tool search**：session 開始時只載入工具名稱與 server instructions，工具定義等 Claude 需要時才載入，所以多接幾個 MCP server 對 context 的影響很小。
- 工具輸出超過 **10,000 tokens** 會顯示警告，預設上限 **25,000 tokens**，可用 `MAX_MCP_OUTPUT_TOKENS` 調整。
- 這也是為什麼 RAG 檢索 server 要回傳**精選的少數片段**，而不是整批文件。

## 七、實務路線

1. **先做 RAG**：把最重要的一兩類文件接起來，建好權限與引用，同時建立評估集。
2. **量測**：用評估集看檢索命中率與答案正確率，找出是檢索壞了還是模型壞了。
3. **缺即時資料或需要動作時，再加 MCP**：先加**唯讀**的查詢 server，寫入類最後加並要求審核。
4. **把 RAG 包成 MCP server**（需要多個應用共用時）：統一權限與稽核入口。
5. **RAG 仍不夠**：才考慮微調或 RL，判斷流程見〈[Post-Training](Post-Training.md)〉。

## 八、常見迷思

| 迷思 | 實情 |
|------|------|
| 用 RAG 就是在訓練模型 | 不改權重；是推論時檢索 |
| 有 MCP 就不需要 RAG | MCP 適合即時資料與動作，不適合在大量非結構化文件上做相關性排序 |
| 有 RAG 就不需要權限控管 | 權限要在索引與檢索層落實，模型不會替你守 |
| 向量檢索一定比關鍵字好 | 精確字串（型號、條款）常常是關鍵字更準，hybrid 通常較穩 🛠 |
| 多接 MCP server 一定吃光 context | Claude Code 預設用 tool search，只先載入名稱 ✅ |
