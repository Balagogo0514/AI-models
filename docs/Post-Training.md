# AI Post-Training

AI 的「後訓練」（post-training）是指模型完成預訓練（pretraining）後，為了讓模型更符合任務需求、回答偏好、安全規範與推理能力，而追加的一系列訓練與優化方法。

簡單說：

- 預訓練解決「模型看過很多資料」
- 後訓練解決「模型更會做事、更像你要的助手」

---

## 後訓練在做什麼

後訓練通常用來改善這幾件事：

- 指令遵循：更會照需求完成任務
- 領域適配：更懂醫療、法律、金融、企業內部知識
- 回答偏好：更符合人類期待的品質、格式與風格
- 安全對齊：降低有害、越獄、違規輸出
- 推理與工具使用：更會做多步推理、調用工具、產出結構化結果

---

## 常見方法

### 1. SFT / 監督式微調

SFT（Supervised Fine-Tuning）是最常見的後訓練方法。做法是用高品質的指令資料、問答資料、範例輸出，直接監督模型學習。

適合場景：

- 指令跟隨
- 摘要、翻譯、分類
- 客服機器人
- 程式助手
- 特定語氣或格式輸出

優點：

- 直接、穩定、成本相對可控
- 是大多數後訓練流程的基礎步驟

限制：

- 模型會模仿資料品質
- 不一定能學到「哪個答案更好」

---

### 2. Continued Pretraining / Domain Adaptation

這類方法是在預訓練後，用特定領域的大量語料繼續訓練模型。雖然有些人把它和狹義 post-training 分開談，但實務上常一起討論。

適合場景：

- 醫療、法律、金融模型
- 公司內部知識或專屬術語
- 特定語言或產業資料強化

優點：

- 能補足模型對領域語料的理解
- 後續再做 SFT 效果通常更穩

限制：

- 需要大量乾淨領域資料
- 成本通常高於一般 LoRA 型微調

---

### 3. Preference Learning / 偏好學習

偏好學習的重點不是只學「正確答案」，而是學「比較好的答案」。常見做法是蒐集 A/B 回答排序，讓模型理解人類偏好。

常見方法：

- RLHF：Reinforcement Learning from Human Feedback
- RLAIF：Reinforcement Learning from AI Feedback
- DPO：Direct Preference Optimization
- IPO、ORPO、SimPO：偏好優化的不同變體

適合場景：

- 幫助模型更自然、更有幫助
- 優化回覆品質、風格、一致性
- 提升拒答與安全對齊表現

優點：

- 能更直接優化「回答品質」
- DPO 類方法通常比完整 RLHF 更容易訓練

限制：

- 偏好資料品質決定上限
- 偏好本身可能主觀且有分佈偏差

---

### 4. RL 後訓練

強化學習後訓練會根據 reward 來優化模型策略，特別適合有可驗證目標的任務。

常見 RL 方式：

- RLHF：用人類偏好資料訓練 reward model，再用 RL 優化模型
- RLAIF：用 AI 來提供偏好訊號或評分，降低人工標註成本
- Verifier-based / Rule-based RL：用規則或驗證器直接給 reward，例如數學答案、單元測試、編譯結果
- Environment / Tool-interaction RL：讓模型和工具或環境互動，再根據任務完成度給 reward
- Self-play / Self-improvement RL：模型自己生成題目、答案、對局或候選解，再透過對抗、比較或篩選學習

常見演算法：

- PPO
- REINFORCE
- Actor-Critic
- GRPO
- TRPO
- 其他基於 reward model 或 verifier 的 policy optimization 變體

適合場景：

- 數學題
- 程式生成與修復
- 長鏈推理
- 有明確評分器或驗證器的任務

優點：

- 能直接針對最終任務結果優化
- 對推理與 search 型問題常有效

限制：

- 訓練不穩定，調參成本高
- reward 設計不當會導致 reward hacking

補充：

- DPO、IPO、ORPO、SimPO 常和 RLHF 放在同一類討論，但嚴格說它們比較屬於偏好優化，不是傳統 RL
- 在 LLM 場景中，最有價值的通常不是通用 control 型 RL，而是能結合 verifier、工具使用與任務完成率的 RL

---

### 5. Rejection Sampling / Best-of-N

這類方法會先讓模型生成多個候選答案，再透過規則、reward model、驗證器或人工方式選出較好的結果。

用途通常有兩種：

- 直接當推論策略：生成多次，挑最好的答案
- 當資料蒐集方式：把篩選後的好答案回灌成 SFT 或偏好資料

優點：

- 實作簡單
- 常能有效提升結果品質

限制：

- 推論成本高
- 需要好的打分或篩選機制

---

### 6. Distillation / 蒸餾

蒸餾是讓大模型當老師，小模型當學生，把能力壓縮到更小、更快、更便宜的模型上。

適合場景：

- 邊緣部署
- 降低推論成本
- 需要高吞吐量的產品

優點：

- 兼顧效果與效率
- 能保留部分大模型能力

限制：

- 小模型仍有容量上限
- 蒸餾資料與 teacher 輸出品質很重要

---

### 7. PEFT / 參數高效微調

PEFT（Parameter-Efficient Fine-Tuning）不是訓練目標，而是訓練方式。它讓你只更新少量參數，而不是整個模型。

常見方法：

- LoRA
- QLoRA
- Adapter
- Prefix Tuning

適合場景：

- 資源有限
- 需要快速做多個任務版本
- 想保留 base model，不做全量改動

優點：

- 成本低
- 訓練快
- 部署靈活

限制：

- 能力上限通常不如全參數訓練
- 對極複雜能力提升未必足夠

---

### 8. Safety / Alignment Tuning

這類後訓練專門針對模型安全、合規與拒答策略做調整。

常見目標：

- 避免違規內容
- 抵抗 prompt injection 或 jailbreak
- 改善拒答邏輯
- 符合產品政策與法規要求

這通常不是單一方法，而是會混合：

- SFT
- 偏好學習
- 規則資料
- 對抗式資料

---

### 9. Tool Use / Agent 能力微調

這類方法讓模型更會：

- 呼叫函式或 API
- 搜尋外部知識
- 使用工具鏈
- 輸出 JSON / schema
- 做多步規劃與任務分解

對 agent 系統來說，這類後訓練很重要，因為它決定模型是否真的能穩定操作工具，而不只是生成文字。

---

## 方法比較

| 方法 | 主要目標 | 優點 | 限制 |
|---|---|---|---|
| SFT | 指令跟隨、格式與任務能力 | 穩定、直接、常作為基礎 | 高度依賴資料品質 |
| Continued Pretraining | 領域知識補強 | 領域適配效果強 | 需要大量語料與算力 |
| Preference Learning | 學習「更好的回答」 | 回答品質提升明顯 | 偏好資料難蒐集 |
| RL | 直接最佳化任務 reward | 對推理/程式/數學有效 | 訓練不穩定、成本高 |
| Rejection Sampling | 從多答案中選好答案 | 簡單有效 | 推論成本高 |
| Distillation | 壓縮能力到小模型 | 降成本、提速度 | 有能力損失 |
| PEFT | 低成本微調 | 快、便宜、彈性高 | 上限受限 |
| Safety Tuning | 安全與合規 | 產品化必要 | 容易影響可用性平衡 |
| Tool/Agent Tuning | 工具調用與流程能力 | 對 agent 產品很關鍵 | 需要高品質任務資料 |

---

## 常見實務流程

現代大模型很常見的後訓練路線是：

1. 預訓練完成
2. 依需求做 continued pretraining 或 domain adaptation
3. 做 SFT，建立基本指令能力
4. 做偏好優化，例如 DPO 或 RLHF
5. 補安全與拒答資料
6. 視需求做 RL、蒸餾或工具使用強化

可簡寫成：

```text
Pretraining
-> Domain Adaptation
-> SFT
-> Preference Optimization
-> Safety Alignment
-> RL / Distillation / Tool Use Tuning
```

---

## 怎麼選

如果目標是：

- 讓模型先變得可用：先做 SFT
- 讓模型更懂特定領域：做 continued pretraining 或 domain adaptation
- 讓回答品質更像人喜歡的樣子：做 DPO / RLHF / RLAIF
- 讓模型在數學、程式、推理上更強：加 RL 或 verifier-based training
- 讓部署更省成本：做蒸餾
- 算力有限但想快速微調：用 LoRA / QLoRA

---

## 一般使用者可做的優化

如果你無法調整大模型權重，能做的通常不是嚴格意義上的 post-training，而是使用層與系統層優化。不過在實務上，這些方法往往比小規模微調更容易落地，也更快見效。

### 1. Prompt 優化

把任務描述得更清楚，通常是成本最低、效果最直接的做法。

常見方法：

- 明確寫出目標、限制條件、成功標準
- 指定輸出格式，例如表格、JSON、固定欄位
- 提供 1 到 3 個高品質範例
- 把大任務拆成幾個步驟，降低模型跑偏機率

---

### 2. Context 優化

模型常常不是不會，而是缺資訊。把對的資訊放進 context，通常比單純改 prompt 更重要。

常見方法：

- 補上需求文件、規格、會議紀錄、程式碼片段
- 用 RAG 或文件檢索把相關資料先找出來再餵給模型
- 過濾不相關內容，避免 context 被雜訊塞滿
- 把背景資訊結構化，例如摘要、欄位化、段落標記

---

### 3. Workflow 優化

不要把模型當成一次性問答工具，而是把它放進一個可重複的流程。

常見方法：

- 先產生草稿，再做第二輪改寫或校對
- 把任務拆成「理解需求 -> 產出候選 -> 自我檢查 -> 最終整理」
- 多次生成，再做人選或規則篩選
- 固定常用 prompt template，降低每次輸入波動

---

### 4. Tool Use 優化

很多問題不是模型本身能力不足，而是缺少外部工具。

常見方法：

- 接搜尋，補最新資訊
- 接計算器或程式執行，降低數學與程式錯誤
- 接資料庫或 API，讓回答依據真實資料
- 接格式驗證器或 schema 檢查器，提升輸出穩定性

---

### 5. Evaluation 優化

如果沒有評測，你通常無法知道 prompt 變更到底是變好還是變差。

常見方法：

- 建立一小組固定測題
- 比較不同 prompt、不同模型、不同參數設定
- 追蹤正確率、穩定性、格式錯誤率、人工修改量
- 對高價值任務做人類審核

---

### 6. 參數與模型選型

即使不能訓練模型，選對模型與參數也能大幅影響效果。

常見方法：

- 推理任務選 reasoning 較強的模型
- 長文件任務選 context window 較大的模型
- 創意寫作可提高 temperature
- 穩定格式輸出可降低 temperature，並限制輸出長度

---

## 一句話理解

不能改模型權重時，最有效的優化通常不是「訓練模型」，而是讓對的資訊，用對的流程，在對的格式下進模型。

---

## 一句話總結

後訓練不是單一技術，而是一整套把「會預測下一個 token 的模型」，變成「能完成任務、符合偏好、可安全部署的模型」的方法組合。
